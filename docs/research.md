# Заметки исследования

## PastVu

Известный endpoint:

```text
GET https://api.pastvu.com/api2?method=photo.giveForPage&params={"cid":2479426}
```

Для первого интеграционного сценария используем метод:

```text
GET https://api.pastvu.com/api2?method=photo.giveNearestPhotos&params={"geo":[55.740058,37.585245],"limit":5,"distance":200}
```

Решение для прототипа:

- при клике на полигон Kontiki берём центр его bounds;
- передаём координаты в `photo.giveNearestPhotos`;
- ограничиваем радиус до 200 м и результат до 5 фотографий;
- показываем найденные фотографии в боковой панели и маркерами на карте.
- показываем только небольшие превью и ссылки на исходные страницы PastVu.

Полезные поля ответа:

- `result.photo.cid`
- `result.photo.file`
- `result.photo.title`
- `result.photo.y`
- `result.photo.year`
- `result.photo.year2`
- `result.photo.geo`
- `result.photo.regions`

Поведение ошибок:

- API возвращает ошибки в JSON.
- HTTP-статус при ошибке может оставаться `200 OK`.
- Интеграционный код должен проверять верхнеуровневое поле `code`.

## Kontiki Maps

Нужно исследовать:

- есть ли публичный API или SDK;
- можно ли добавлять пользовательские маркеры;
- какие форматы импорта данных поддерживаются;
- есть ли iframe или другой механизм встраивания;
- какие есть лицензионные и пользовательские ограничения.

Страница набора данных:

```text
https://kontikimaps.ru/how-old/cities250/datasets?p=cities250
```

Известные факты о наборе данных:

- данные распространяются в формате GeoPackage (`.gpkg`);
- на странице указана лицензия Open Data Commons Open Database License (ODbL);
- набор содержит 80 городов России;
- для первого прототипа можно взять только Москву, чтобы уменьшить объём проверки.
- слой данных называется `all_cities_181123`;
- в слое 3 550 042 объекта;
- система координат: `EPSG:3857`;
- поле `city` хранит техническое название города латиницей.

Значения для Москвы:

| city | city_russian | city_english | Объектов |
| --- | --- | --- | ---: |
| `old moscow` | Москва (старая) | Moscow (main) | 159 412 |
| `new moscow` | Новая Москва | New Moscow | 97 523 |

Для первой итерации берём `old moscow`. Новую Москву пока оставляем за пределами прототипа, чтобы сократить объём данных и сфокусироваться на историческом центре.

Первый тестовый fixture:

- файл: `data/fixtures/old-moscow-sample.geojson`;
- объём: 100 объектов;
- размер: около 120 КБ;
- CRS: `EPSG:4326`;
- геометрия: `MultiPolygon`;
- назначение: быстрая проверка карты и состава полей без полного GeoPackage.

Рабочие fixture-файлы для первой полезной версии:

- папка: `data/fixtures/old-moscow-periods/`;
- объём: 110 598 объектов;
- фильтр: старая Москва, годы `1357—2021`, только объекты с адресом;
- CRS: `EPSG:4326`;
- геометрия: `MultiPolygon`;
- разбиение: отдельный GeoJSON на каждый период цветной шкалы;
- назначение: поиск домов выбранного исторического периода для прогулок без загрузки всей Москвы одним файлом.

Поля Kontiki, которые используются в интерфейсе:

| Поле | Назначение |
| --- | --- |
| `r_name` | название объекта, если оно указано |
| `r_adress` | адрес здания |
| `r_year_int` | числовой год для фильтрации |
| `r_years_str` | строка года или диапазона для отображения |
| `r_floors` | количество этажей |
| `city`, `city_russian`, `city_english` | проверка, что fixture относится к старой Москве |
| геометрия `MultiPolygon` | контур кликабельного здания |

Поля, связанные с архитектором, ссылками, авторскими правами и внешними идентификаторами, пока не выводятся. Для первого сценария они не нужны; если добавлять их позже, нужно отдельно проверить заполненность и условия использования.

Фильтр по годам:

- диапазон шкалы взят по примеру Kontiki Maps: `1357—2021`;
- подпись первого деления в прототипе начинается с `1357`, чтобы совпадать с минимальным значением верхнего ползунка;
- объекты Kontiki фильтруются по полю `r_year_int`;
- объекты без года показываются только при полном диапазоне шкалы;
- при запросе ближайших фотографий PastVu выбранный диапазон передаётся как `year` и `year2`.
- цветная шкала показывает исторические периоды как равные визуальные сегменты, как в Kontiki Maps;
- точный выбранный диапазон показывается над ползунком;
- клик по цветному сегменту выбирает соответствующий диапазон годов.

Данные подгружаются лениво: при выборе диапазона приложение загружает только те периодные GeoJSON-файлы, которые пересекаются с выбранными годами. По умолчанию выбран диапазон `1917—1953`, чтобы не загружать всю Москву при первом открытии.

## Яндекс Карты

Исходная пользовательская проблема: на карте Kontiki Maps трудно быстро понять, где находится выбранный район и какое метро рядом.

Для первой версии прототипа не используем API Яндекс Карт. При клике на объект строим обычную внешнюю ссылку на Яндекс Карты по центру полигона:

```text
https://yandex.ru/maps/?ll=<longitude>,<latitude>&z=17
```

Так пользователь может открыть выбранное место в привычной карте и дальше смотреть метро, маршруты и панорамы уже в интерфейсе Яндекса.

Почему это решение подходит для первой итерации:

- не нужен API-ключ;
- прототип не зависит от коммерческих условий API;
- мы не сохраняем и не обрабатываем данные Яндекс Карт;
- пользовательская задача решается быстрее, чем через встраивание отдельной карты.

Ограничение: ссылка строится по центру полигона. Для большинства зданий этого достаточно, но для сложных контуров точка может быть не идеальной.

Заметка о лицензии:

- Лицензию кода проекта нужно отделять от лицензии внешних данных.
- Если в репозитории появятся данные, производные от Kontiki, нужно отдельно описать атрибуцию и требования ODbL share-alike.
- В документации репозитория лучше не писать «вирусная лицензия»; точнее использовать «ODbL» или «лицензия с требованием share-alike».

## Варианты прототипа

Вариант 1: статический frontend с маркерами на карте.

Вариант 2: статический frontend и локальный JSON-fixture.

Вариант 3: frontend и небольшой backend-прокси, если прямые запросы заблокируют CORS или лимиты.

## Картографическая подложка

Для прототипа используем тёмную подложку CARTO Dark Matter. Она построена на данных OpenStreetMap и лучше подходит для сценария с цветными историческими периодами: дома заметнее, чем на светлой стандартной карте.

Важно отделять подложку карты от данных Kontiki:

- подложка отвечает за улицы, кварталы и ориентиры;
- слой Kontiki отвечает за цветные дома и годы постройки;
- слой PastVu отвечает за найденные рядом фотографии.
